# JIMWLK Solver

A C++ code that solves the JIMWLK evolution equation using the Langevin step method.

Originally written by Björn Schenke, with modifications by Heikki Mäntysaari <heikki.mantysaari@jyu.fi>

Website: https://github.com/hejajama/jimwlk

Note: this program can directly evolve Wilson line configurations generated by running [IP-Glasma](https://github.com/schenke/ipglasma)

## Compilation

### Prerequisites

The code requires the following libraries:
- **GSL** (GNU Scientific Library)
- **FFTW** (Fast Fourier Transform library)
- **Boost**
- **CMake** (version 3.0 or later)

### Build Instructions

To compile the code:

```bash
mkdir build
cd build
cmake ..
make
```

The binary file is generated in `build/bin/jimwlk`.

## Running the Code

### Basic Usage

The code reads parameters from an input file. To run with a specific input file:

```bash
./build/bin/jimwlk my_input_file
```

If no input file is specified, the code defaults to using a file named `input`:

```bash
./build/bin/jimwlk
# uses default "input" file
```

### Input File Format

The input file contains all simulation parameters. See the example `input` file in the repository for a template. Each parameter is specified as:

```
parameterName value
```

The file must end with `EndOfFile`.

## Input Parameters

All parameters that can be set in the input file are described below:

### Evolution Control

- **mode** (integer): Operation mode
  - `1`: Run JIMWLK evolution
  - `2`: Analysis mode (process previously saved Wilson lines from disk, legacy, may not work)

- **initMethod** (integer): Initial condition generation method
  - `1`: Gaussian initial condition
  - `2`: McLerran-Venugopalan (MV) model
  - `3`: MV model with quartic ρ⁴ term
  - `10`: Read from text file (use `input_wline` parameter)
  - `11`: Read from binary file (use `input_wline` parameter)

- **g2mua** (double): The product g²μ×a, which sets the initial saturation scale if the initial condition is not read from file. μ is the saturation momentum scale and a is a parameter.

- **kappa4Factor** (double): Factor multiplying the ratio of κ₄/(g²μ²)³ for the quartic term in the initial condition (only with `initMethod 3`)

- **g** (double): Coupling constant g. Required for initial condition generation.

- **R** (double): controls the target size when initial condition is generated

- **steps** (integer): Number of rapidity evolution steps

- **measureSteps** (integer): Interval between measurements. Observables are computed and saved every `measureSteps` evolution steps.

- **ds** (double): Rapidity step size (Δs in the evolution equation)

- **simpleLangevin** (integer): Langevin solver variant
  - `0`: Use standard form with deterministic term
  - `1`: Use simplified form from arXiv:1212.4825 (faster, less memory required)

### Running Coupling

- **runningCoupling** (integer): Enable running coupling behavior
  - `0`: Fixed coupling (αₛ is constant)
  - `1`: Running coupling

The strong coupling constant αₛ is calculated using 1-loop running coupling formulas:

**At running coupling (runningCoupling = 1):**
$$\alpha_s(r) = \frac{4\pi}{\frac{11N_c - 2N_f}{3} \ln\left[\left(\frac{\mu_0^2}{\Lambda_{QCD}^2}\right)^{1/c} + \left(\frac{4}{r^2\Lambda_{QCD}^2}\right)^{1/c}\right]^c}$$

The code uses hardcoded $c=0.2$. Currenlty the code only supports the *square root* coupling discussed e.g. in [2104.14254](https://arxiv.org/pdf/2104.14254) (eq 46) and [1212.4825](https://arxiv.org/abs/1212.4825).

- **mu0** (double): Infrared cutoff scale to avoid Landau pole in 1-loop running coupling expression. This is in GeV

- **Lambda_QCD** (double): QCD scale parameter in GeV. Used for running coupling calculations.





### Infrared Regulation

- **m** (double): Infrared mass regulator (in GeV) that suppresses long-distance Coulomb tails. See arXiv:1407.8458 for details. Set to 0 for no regulator.

- **L** (double): Lattice length in femtometers

### Lattice and SU(Nc) Parameters

- **size** (integer): Lattice size (number of cells per side). Preferably a power of 2 (e.g., 128, 256, 512), but can be anything. Larger values improve spatial resolution but increase computation time and memory requirements.

- **Nc** (integer): Number of colors for SU(Nc) gauge group (2 and 3 supported)


- **Ny** (integer): Longitudinal resolution parameter. See Lappi, Eur. Phys. J. C55,285 for details.


### Initial Conditions from File

- **input_wline** (string): Filename containing pre-generated Wilson lines to use as initial conditions (when `initMethod` is 10 or 11). Note: the lattice size and Nc must match between the input file and these Wilson lines.

- **output_dir** (string): Directory where to save evolved Wilson lines. Created if it doesn't exist. Filenames contain the step number (format: `inputfile_steps_s`).

### Random Number Generation

- **seed** (integer): Random seed added to the current time for PRNG initialization. Different seeds give different random realizations.

## Mapping evolution steps to evolution rapidity

The evolution steps are directly proporional to the evolution rapidity $y = \ln (x_0/x)$, depending on the running coupling scheme.

### Fixed Coupling
$$\text{steps} = \frac{\alpha_s \ln(x_0/x)}{\pi^2 \, ds}$$


### Running Coupling
$$\text{steps} = \frac{\ln(x_0/x)}{\pi^2 \, ds}$$

where:
- `ds` is the rapidity step size (from input file)
- `x₀` Initial condition, typically 0.01

## Output Files

- **usedParameters.dat**: Log file created during each run containing all parameters used for that run.
- **evolved_wilson_lines/**: Directory containing saved Wilson line configurations at different evolution steps (if `output_dir` is set to `evolved_wilson_lines/`).

## Notes on Running Coupling

When using running coupling (`runningCoupling = 1`), the infrared mass parameter `m` regulates the infrared divergence. This parameter should be on the order of ΛQCD and is given in GeV. See arXiv:1407.8458 for theoretical details.
